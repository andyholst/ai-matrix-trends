# Auto-Commit Checkpoint Workflow with Stop Hooks and Git

## Core Idea
Using Claude Code's `Stop` hook to automatically create a git checkpoint commit at the end of every AI coding session — giving developers rollback points, branch isolation for parallel sessions, and an audit trail of what the agent changed.

## Details
Claude Code's `Stop` hook fires when a session completes. The hook receives a JSON payload on stdin containing `session_id`, `transcript_path`, `cwd`, and `stop_hook_active`. The transcript is a JSONL file with every user message and assistant response — a complete record of what happened.

GitButler (a GitHub-backed startup) popularized this pattern to automatically commit agent work into isolated virtual branches. The pattern works with plain git too, using a simple shell script.

### Basic Stop Hook Configuration

In `~/.claude/settings.json`:

```json
{
  "hooks": {
    "Stop": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "${HOME}/.claude/scripts/auto-commit.sh",
            "timeout": 30
          }
        ]
      }
    ]
  }
}
```

### The Auto-Commit Script

```bash
#!/usr/bin/env bash
set -euo pipefail

# Parse the Stop hook payload
payload=$(cat)
session_id=$(echo "$payload" | jq -r '.session_id')
transcript=$(echo "$payload" | jq -r '.transcript_path')
cwd=$(echo "$payload" | jq -r '.cwd')

# Only commit if there are changes
cd "$cwd"
if git diff --quiet && git diff --cached --quiet; then
  exit 0
fi

# Extract the user's original prompt as commit message
prompt=$(head -1 "$transcript" | jq -r '.message.content // empty' | head -c 200)
[ -z "$prompt" ] && prompt="Claude checkpoint: $session_id"

# Stage everything and commit
git add -A
git commit -m "🤖 Claude checkpoint

Session: $session_id
Trigger: $prompt

Auto-generated by Claude Code Stop hook"

echo "Checkpoint committed: $(git rev-parse --short HEAD)"
```

### Multi-Session Branch Isolation

When running multiple Claude Code sessions in parallel (e.g., one per microservice), the `session_id` in the payload lets you route each session's commits to its own branch:

```bash
# In the Stop hook script
branch="claude/${session_id:0:8}"
git checkout -b "$branch" 2>/dev/null || git checkout "$branch"
git add -A
git commit -m "checkpoint: ${session_id:0:8}"
```

Each parallel agent works on its own branch. No conflicts, no interleaved commits. Reviewers can cherry-pick or discard branches independently.

### GitButler Integration

GitButler's production deployment uses this pattern at scale. Their client:

1. Detects Claude Code `Stop` events via hooks
2. Reads the transcript to determine what the agent was working on
3. Creates a virtual branch per topic (not just per session)
4. Commits with structured messages including the session ID and task description

This means five parallel agent sessions produce five organized branches like `claude/auth-refactor`, `claude/fix-payment-flow`, `claude/update-deps` — not five messes on `main`.

### Safety Considerations

- The hook runs in a non-interactive shell — it cannot prompt or accept input
- `stop_hook_active` prevents infinite loops (a Stop hook that triggers another Stop)
- The script should exit 0 even on commit failure (non-blocking) unless you want to block
- Consider adding `git config user.email` and `git config user.name` in the script for headless environments

## Implications
The auto-commit pattern turns AI coding sessions from risky (uncommitted changes, lost work) into safe (every session is a checkpoint). Combined with branch isolation, it makes parallel agent workflows practical — you can run 5 agents simultaneously and review 5 clean branches instead of one tangled diff. The transcript-as-commit-message approach also creates a searchable history: `git log --grep="🤖 Claude"` shows everything the agent did.
