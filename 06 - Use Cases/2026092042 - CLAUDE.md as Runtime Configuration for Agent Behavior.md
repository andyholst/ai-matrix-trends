# CLAUDE.md as Runtime Configuration for Agent Behavior

## Overview

CLAUDE.md (and its equivalents AGENTS.md for Codex, GEMINI.md for Gemini CLI) is a hierarchical configuration file that shapes how an AI coding agent behaves in a project. An empirical study of 328 public Claude Code projects (arXiv:2511.09268) found that 72.6% of configuration files specify architectural constraints, 44.8% define general development guidelines, and 39% provide project overview. The most common pattern combines architecture rules, dependency management, and project overview. These files function as runtime configuration — not documentation — and are the primary mechanism for aligning agent behavior with team standards.

## Setup

```bash
# Create a project-level CLAUDE.md
touch CLAUDE.md

# Claude Code automatically discovers and reads:
#   ~/.claude/CLAUDE.md          (global, all projects)
#   ./CLAUDE.md                 (project root)
#   ./src/CLAUDE.md             (directory-level, overrides parent)
```

## Configuration

```markdown
# CLAUDE.md

## Architecture
- Zero-dependency core package pattern: interfaces in core/, implementations in feature packages
- Components wired via dependency injection
- Each component has an interface in the core package

## Bash commands
- npm run build: Build the project
- npm run typecheck: Run the typechecker
- uv run pytest: Run tests (prefer single tests over full suite)

## Code style
- Use ES modules (import/export) syntax, not CommonJS (require)
- Destructure imports when possible
- Prefer `X | Y` over `Union[X, Y]`

## Workflow
- Run typecheck after making a series of code changes
- Prefer running single tests, not the whole test suite
- If unsure about something, ask for clarification rather than making up an answer
```

## Workflow

1. **Write the config** — Define architecture constraints, coding style, available commands, and workflow rules in CLAUDE.md at the project root.
2. **Layer hierarchically** — Place global rules in `~/.claude/CLAUDE.md`, project rules in `./CLAUDE.md`, and directory-specific overrides in subdirectories. Files closer to the working directory take priority.
3. **Feed to the agent** — The agent reads the file automatically at session start. For long sessions, re-sync by referencing the config: "Per CLAUDE.md, use ES modules — refactor this file."
4. **Iterate** — Update the config as the project evolves. Treat it as runtime config, not static documentation.

## Results

- Reduces off-script behavior and unwanted patterns
- Outputs require less tweaking and integrate more smoothly with the codebase
- Acts as onboarding for a new hire — the agent learns your conventions upfront
- Hierarchical layering allows team-wide standards with project-specific overrides
- 60,000+ projects used AGENTS.md configuration files as of December 2025 (OpenAI)
